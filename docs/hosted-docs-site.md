# Hosted documentation site

Patchline's hosted documentation site is generated by `scripts/build-docs-site.sh` and published by `.github/workflows/docs.yml` to GitHub Pages at `https://thehalleyyoung.github.io/patchline/`.

The site is intentionally static, but it is not hand-waved. The build regenerates a pinned public-repository analysis and runs a stable local command suite against `demos/billing`, then publishes the resulting JSON under `artifacts/` so maintainers, researchers, security reviewers, and contributors can audit the numbers shown on the pages.

```bash
bash scripts/build-docs-site.sh \
  examples/docs-site-gate.json \
  results/generated/docs-site-gate
```

## Site map

The generated site contains:

- `index.html`: landing page with public-repo metrics and local command proof.
- `quickstart.html`: copy/paste local pipeline using the same commands the build runs.
- `architecture.html`: fetch, inventory, intake, baseline, proposal, compare, and CI/offline layer map.
- `scenarios/local-analysis.html`: local workspace and migration-folder analysis.
- `scenarios/public-repositories.html`: pinned public-repo analysis and public matrix guidance.
- `scenarios/generated-interventions.html`: generated-code quarantine and compare workflow.
- `scenarios/database-semantics.html`: dialect-aware SQL semantics review.
- `scenarios/ci-offline.html`: GitHub Pages deployment, CI, redaction, and offline validation guidance.
- `tutorials/maintainers.html`: maintainer workflow for first-run analysis, triage, generated artifacts, and review handoff.
- `tutorials/researchers.html`: claims-to-evidence workflow, public slices, limitations, and artifact gates.
- `tutorials/security-reviewers.html`: threat model, generated-code quarantine, release integrity, and offline checks.
- `tutorials/contributors.html`: contributor checks, fixtures, plugins, and docs standards.
- `reference/commands.html`: command samples generated from successful local runs.
- `reference/artifacts.html`: which JSON/Markdown/SARIF/patch files to hand to reviewers.
- `reference/validation.html`: the gates that reproduce the docs and broader repository claims.
- `artifacts/public-demo.json`: public `lobsters/lobsters` analysis summary regenerated during the build.
- `artifacts/command-results.json`: command strings, exit codes, and output paths for the documented local command samples.
- `sitemap.xml`, `.nojekyll`, and `site-manifest.json`: hosting metadata for GitHub Pages.

## Verified command samples

The docs build runs these local commands before writing the site:

1. `go run ./cmd/patchline about`
2. `go run ./cmd/patchline doctor demos/billing --out <local>/doctor`
3. `go run ./cmd/patchline intake demos/billing --out <local>/intake`
4. `go run ./cmd/patchline repo inventory demos/billing --out <local>/inventory --json`
5. `go run ./cmd/patchline repo baseline --inventory <local>/inventory --intake <local>/intake --out <local>/baseline --json`
6. `go run ./cmd/patchline repo propose --from-report <local>/baseline --proposal-kind all --budget files=3,lines=80,tokens=8000,changes=2 --no-llm --out <local>/proposal --json`
7. `go run ./cmd/patchline repo compare --before <local>/baseline --after <local>/proposal --out <local>/compare --json`
8. `go run ./cmd/patchline db-semantics --engine postgres --sql demos/billing/migrations/002_bad_backfill.sql --out <local>/db-semantics.json`
9. `go run ./cmd/patchline plugins list`
10. `go run ./cmd/patchline plugins probe demos/billing --out <local>/plugins-probe`

Those commands are intentionally based on committed fixtures so `make docs-site-gate` can verify the examples without needing private services. The public demo is still regenerated from a pinned GitHub ref so the landing page demonstrates real repository behavior.

## Validation contract

Run:

```bash
make docs-site-gate
```

The gate rebuilds the site and verifies:

- GitHub Pages workflow uses `actions/deploy-pages`.
- Every required page in `examples/docs-site-gate.json` exists.
- Role tutorials exist for maintainers, researchers, security reviewers, and contributors.
- `artifacts/public-demo.json` meets the configured public-repo thresholds.
- `artifacts/command-results.json` contains every required command sample and all samples exited successfully.
- Internal HTML links resolve inside the generated site.
- `site-manifest.json` records pages, roles, public-demo summary, and command-result summary.

If a future doc claim adds a new command block, add it to the generated command-results path or to a focused make gate before publishing it.
