# Patchline semantics

Patchline treats a production system as a program whose state includes code, schema, rows, jobs, queues, reports, deploys, migrations, traces, policies, repair records, and audit ledgers. Historical telemetry is a partial execution trace of that program. A repair manifest is a partial state transformer: it is defined only when its scope, preconditions, rollback requirements, policy gates, and replay state are available.

The implementation exposes this model as a hashable semantic contract:

```bash
go run ./cmd/patchline semantics-contract
```

Current contract:

```text
Patchline semantic contract patchline.semantics/v1 hash=420d1a803b4380e68f04ea0cde65064ffefabc62d300c4fa617fc4a41c9b4bfb
  state components=8 observations=5 commands=30 failure states=6
```

## Semantic contract

Every Patchline command should emit at least one checkable semantic artifact:

| Artifact | Must emit | Existing command examples |
| --- | --- | --- |
| Trace projection | Facts and hashes | `ingest-evidence`, `slice`, `demo-graph` |
| Repair contract | Facts, obligations, hashes | `validate-repair`, `lint-repair --proof` |
| Replay report | Facts, hashes, counterexamples | `dry-run`, `effect-summary` |
| Replay semantics | Small-step states, commutativity/confluence facts, isolation hazards, hashes, counterexamples | `repair-semantics` |
| Invariant report | Declarations, before/after checks, counterexamples, candidates | `check-invariants`, `discover-invariants` |
| Migration report | Facts, obligations, hashes | `analyze-migration` |
| Schema semantics | Schema diffs, relational-signature transformations, relational statements, hashes | `schema-diff`, `migration-semantics` |
| Source SQL inventory | Embedded SQL, ORM/query-builder observations, framework/language counts, hashes | `extract-sql` |
| Migration outcome history | Migration-to-trace/row/report/repair/policy links, semantic changelog, hashes | `migration-outcomes`, `migration-changelog` |
| Solver obligations | Bounded SMT-style scope, frame, row-count, and invariant checks, hashes, counterexamples | `solver-obligations`, `semantics-audit` |
| Symbolic execution | Bounded row paths, path constraints, symbolic assignments, hashes, counterexamples | `symbolic-exec`, `semantics-audit` |
| Workflow model check | Bounded workflow states, temporal properties, proof obligations, proof holes, counterexamples | `model-check-workflow`, `semantics-audit` |
| CEGAR refinement | Iterative abstraction refinement, remaining proof holes, hashes, counterexamples | `cegar-refine`, `semantics-audit` |
| Signed attestation | Ed25519 signature facts over semantic artifact hashes | `sign-artifact`, `verify-artifact` |
| Incident archive | Evidence-shape, migration-risk/table, repair-effect, policy-decision, and benchmark-decision buckets | `archive-index`, `semantics-audit` |
| Benchmark report | Facts, obligations, counterexamples, hashes | `benchmark-suite`, `ci-gate` |
| Ledger checkpoint | Facts and hashes | `ledger-verify` |

The contract is generated by `internal/semantics` and grounded in existing packages rather than a second ontology: state kinds come from `internal/provenance`, repair effects come from `internal/effects`, executable repair semantics come from `internal/repair` and `internal/replay`, and hashes come from `internal/canonical`.

## State model

| State component | Current representation | Role |
| --- | --- | --- |
| Code | `service`, `commit`, `deploy` provenance entities | Versioned program text and rollout state |
| Schema | `migration` entities and migration reports | Relational signature and migration history |
| Rows | `record` and `sql_mutation` entities plus replay store rows | Persistent data state and row-level mutations |
| Jobs and queues | `job_run`, `queue_event` entities | Asynchronous program state |
| Reports | `report` entities and attestations | Customer-visible derived outputs |
| Traces | `trace` entities and observed edges | Runtime execution observations |
| Policies | policy and gate reports | Review constraints over repair application |
| Ledgers | ledger entries and checkpoints | Tamper-evident repair history |

## Observation model

Observations are partial facts about the state and transitions. Patchline currently supports alerts/spans, row predicates, traces, SQL mutation fingerprints, derived records, derived reports, approval/policy artifacts, and ledger checkpoints. Ingested evidence is intentionally allowed to preserve unknown source-system fields while still emitting typed graph facts and stable hashes.

## Repair transformer

A repair is modeled as a partial transformer:

```text
{ historical evidence + preconditions + scope + snapshot }
  repair manifest
{ replay report + postconditions + rollback/transaction artifacts + hashes }
```

Its domain is the manifest, the historical evidence graph, a current or reconstructed store snapshot, and declared preconditions. Its codomain is a deterministic replay report, row diffs, downstream entity set, SQL plan, rollback plan, transaction plan, and ledger checkpoint. Failure states are explicit: precondition unmet, scope escape, unsupported operation, stuck replay, rollback unavailable, and counterexample found.

`lint-repair --proof` now materializes the repair transformer as a proof report: a Hoare-triple view, weakest preconditions for supported operations, syntactic frame conditions, SQL refinement checks, counterexamples, and a stable hash. Claims are classified as `proved`, `checked`, `assumed`, `unsupported`, or `refuted`. Current executable checks mostly produce `checked` claims; declared SQL pre/postconditions and database facts such as row existence are surfaced as proof holes until an invariant/query checker discharges them.

`effect-summary` materializes the abstraction relation for replay: concrete row diffs are mapped to row-count bounds, changed-column sets, downstream impact, and an effect-lattice join. The emitted summary includes the abstraction/concretization relation and a stable hash, so abstract interpretation claims can be benchmarked against real dry-run outputs.

`repair-semantics` materializes replay as a small-step transition system. Each operation emits a rule, pre/post store hash, touched rows, and one of `normal`, `error`, `stuck`, or `unknown`. Multi-operation manifests also get syntactic independence checks, fixture-observed commutativity, bounded dependency-valid confluence checks, modeled isolation hazards for read committed, repeatable read, snapshot, and serializable execution, plus compensating-action semantics for append-only logs, event streams, queues, logical replays, and derived rebuilds.

`snapshot-drift` runs the same repair over two imported historical row snapshots and compares matched rows plus concrete row-diff hashes. Stable comparisons become checked evidence; drift becomes a strict counterexample showing where replay behavior changed over time.

`schema-diff` and `migration-semantics` materialize migrations as transformations over relational signatures. The first checks an applied migration against an expected schema fixture; the second emits typed schema transformations and relational statement summaries for supported DDL/DML fragments.

`extract-sql` materializes source-code data effects as an inventory of SQL literals, migration-framework DSL operations, and ORM/query-builder calls across representative production languages. Raw SQL is fingerprinted and passed through migration risk/effect analysis; ORM calls remain lower-confidence observations with explicit framework, operation, table, and snippet hashes.

`migration-outcomes` materializes migration history as an observed outcome graph: migration entities link to traces, SQL mutations, row mutations, derived records/reports, repair manifests, policy failures, benchmark hashes, and source-SQL hashes. The same report includes a semantic changelog that lists changed tables, broad effects, observed downstream outcomes, invariant candidates, and reproducibility hashes.

`solver-obligations` materializes a bounded SMT-style proof report. It emits quantifier-free equality SMT-LIB queries for scope implication, checks assignment frames against protected scope columns, enumerates finite store row-count bounds, replays the repair over a bounded store, and checks invariant preservation before and after replay. Claims are classified as `proved`, `checked`, `assumed`, `not_supported`, or `counterexample` in the solver report and are projected into the semantic audit's standard claim statuses.

`symbolic-exec` materializes small repair programs as bounded row-path executions. Each step records the operation, pre/post store hashes, guard constraints over row symbols, satisfying and unsatisfying paths, and symbolic assignments for rows that the operation touches.

`model-check-workflow` materializes incident review as a bounded transition system over ingest, explain, approve, dry-run, apply, verify, rollback, audit, and archive states. It checks temporal properties, emits standardized proof obligations, produces counterexample traces for invalid workflows, and records proof holes when claims require stronger evidence.

`cegar-refine` materializes counterexample-guided abstraction refinement over the current repair. The first iteration runs replay semantics, solver obligations, and symbolic execution over the bounded store; if invariant or workflow evidence is supplied, a second iteration reruns with those refinements and reports whether proof holes decreased or new counterexamples appeared.

`sign-artifact` and `verify-artifact` materialize tamper-evident review evidence. The signature covers an artifact hash, subject, algorithm, and public key, so CI can attach signed approvals to semantic audits, refinement reports, proof bundles, dry-runs, or gate results.

`archive-index` materializes historical incident retrieval as a deterministic semantic artifact. Each indexed incident links evidence, migration analysis, repair replay/effect summaries, policy evaluation, and benchmark results, then buckets incidents by graph shape, migration tables/risk, repair effect, policy decision, and benchmark decision.

`check-invariants` adds executable semantic predicates over reconstructed snapshots before and after replay. Current declarations cover uniqueness, foreign keys, enums, sums, counts, materialized reports, ledger balance, and customer-visible grouped totals. `discover-invariants` emits support-backed candidates separately from enforced declarations so historical knowledge extraction stays auditable.

## Historical conformance audit

The audit command runs the semantic contract against existing real-world-like incident fixtures:

```bash
go run ./cmd/patchline semantics-audit
```

It currently checks the bad-migration evidence JSONL, trace reconstruction, causal certificate, repair manifest, replay report, replay semantics, invariant report, solver obligations, symbolic execution, workflow model checking, CEGAR refinement, generated SQL, transaction plan, migration analysis, schema semantics, source SQL inventory, strict benchmark corpus, migration outcome history, incident archive index, and ledger checkpoint. The default audit output is:

```text
semantic audit passed artifacts=20 conforming=20 proof_holes=7 counterexamples=0 hash=3d204d71488c0aa64f3c2a24e364edcaa907ea8d7f44e04e9077043aab3bf529
```

This is intentionally not a proof of all properties. It is an executable inventory of facts, obligations, proof holes, counterexamples, and hashes over historical artifacts, which gives later formal-methods work concrete obligations to discharge.

## Trace reconstruction and import equivalence

Evidence ingestion now has a trace-projection layer:

```bash
go run ./cmd/patchline trace-reconstruct examples/incidents/bad-migration.jsonl
go run ./cmd/patchline trace-equivalence examples/incidents/bad-migration.jsonl examples/incidents/bad-migration.jsonl
```

The projection records typed observations, source confidence, clock confidence, normalized time intervals, and a semantic projection hash. Import equivalence compares those typed observations rather than raw JSON text, so source exports can be independently converted and checked for the same reconstructed incident trace.
